The problem
  • There is a gap between reading a blog and experiencing a system running live.
  • Simulations fill the gap. Not exact, but still better.
  • You see the system in action.

story→playbook (JSON)→run→report

How it works

The playbook
The initial state (components, dashboards, metrics, alerts), a timeline of events, and a report. A small required core, free-form text everywhere else.
The player
One generic page. Nobody operates anything: the engine plays the playbook deterministically. Space plays and pauses, ←/→ jump between key moments, R opens the report, H switches to Hardcore for the deeper layer.
The skill
story-to-playbook turns a blog post, postmortem, concept or short prompt into a validated playbook file. It writes that one file and nothing else.
